## Bug 排查 2：insert 报 Field 'id' doesn't have a default value（已定位）

- 用户自己写了 Insert 测试（狂神教程同款），实体加了 `@TableId(type = IdType.AUTO)`，yml 也简化了（去掉了 global-config/type-aliases-package）。
- 报错：`DataIntegrityViolationException` ← `java.sql.SQLException: Field 'id' doesn't have a default value`，生成的 SQL 为 `INSERT INTO user (name, age, email) VALUES (?, ?, ?)`（无 id 列）。
- 用 pymysql `SHOW CREATE TABLE` 验证：user 表 id 列 bigint NOT NULL + PRIMARY KEY，但**没有 AUTO_INCREMENT**（EXTRA 为空）。
- 根因：`IdType.AUTO` 让 MP 省略 id 等数据库自增；但表没声明自增，MySQL 不知道 id 填啥 → 两边互相等 → 报错。用户建表时漏了 AUTO_INCREMENT。
- 修复方案（交给用户执行）：`ALTER TABLE user MODIFY id BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID';`（id 已是主键，加自增即可，现有 5 条数据不受影响，下一条插入 id=6）
- 备选方案：`IdType.AUTO` 改 `IdType.ASSIGN_ID`（雪花算法，MP 自己生成 19 位 id，不依赖表自增）。
- 日志里 Thymeleaf "Cannot find template location" 和 Mockito self-attach 警告均为噪音，与此无关。

## Bug 排查 3：时间自动填充不生效（已定位）

- 用户新增 MyMetaObjectHandler（@Component + MetaObjectHandler），实体 User 加了 @TableField(fill=INSERT/INSERT_UPDATE) 的 createTime/updateTime 字段。
- 根因：**类型不匹配** —— 实体字段是 `java.util.Date`，填充器 `strictInsertFill(metaObject, "createTime", LocalDateTime.class, LocalDateTime.now())` 声明的是 LocalDateTime。strictInsertFill 内部做 `fieldType.equals(实体字段类型)` 严格比较，不等就**静默跳过**（不报错、不打日志），handler 明明被调用但填不上。
- 佐证：表里 id=2104126258068865030 那条 create_time/update_time 都填上了（19:28:20），说明两边类型一致时机制正常。
- 修复方案（已给用户，二选一）：A（推荐）实体字段改 LocalDateTime，handler 不动；B 实体保持 Date，handler 改 `strictInsertFill(..., Date.class, new Date())`。
- 顺手发现的第二个问题：updateFill 里调的是 `strictInsertFill`，应为 `strictUpdateFill`（当前因 updateTime 是 INSERT_UPDATE 碰巧能跑，语义不对）。
- 提前排雷：表里 create_time 列误加了 `ON UPDATE CURRENT_TIMESTAMP`（教程里该属性属于 update_time），会导致每次 UPDATE 刷新"创建时间"，建议 ALTER 去掉。
- 附带发现：中途试过 ASSIGN_ID（表里有雪花 id），InnoDB 自增计数器被顶到 2104126258068865033，后续自增 id 会变成巨长数字（非 bug，仅提醒）。
