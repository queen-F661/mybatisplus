## mybatisplus 项目：单元测试失败排查（已定位根因）

- 用户报 MybatisplusApplicationTests.contextLoads 测试失败，只给了 Navicat 截图（mybatisplus 库 user 表 5 条数据正常）。
- 排查过程：检查了 pom.xml / application.yml / UserMapper / User / 主启动类（@MapperScan 已有）；确认 target 编译产物齐全、.m2 里 mybatis-plus-spring-boot4-starter 3.5.17 与 Spring Boot 4.1.1 依赖解析正常；用 Python + pymysql 以 root/123456 直连 localhost:3306/mybatisplus 成功并查出 user 表 5 行（证明账号密码库表都没问题）。
- 用 IDEA 自带 Maven（D:\idea\IntelliJ IDEA 2026.2.3\plugins\maven-plugin\lib\maven3\bin\mvn.cmd，JAVA_HOME=D:\java）真实跑测试，抓到根因：
  - `java.sql.SQLException: Unsupported character encoding 'utf8mb4'` → `java.io.UnsupportedEncodingException: utf8mb4`
  - 根因：application.yml 的 JDBC URL 里 `characterEncoding=utf8mb4` 填了 MySQL 字符集名；该参数要求填 Java 字符集名（UTF-8），驱动内部会 `String.getBytes("utf8mb4")` 直接失败，连接建不起来。
  - 修复：URL 改为 `characterEncoding=UTF-8`（驱动会自动映射到 MySQL 的 utf8mb4）。
- 顺手发现的隐患（非本次失败原因）：`mybatis-plus.type-aliases-package: com.example.mybatisplus.entity` 指向不存在的包，实际实体在 `com.example.mybatisplus.pojo`。
- 环境坑位备忘（可复用）：本机 Git Bash shim 残废（head/ls 异常）；PowerShell 工具直接输出被吞，需 `Out-File` 写文件再用 Read 读；mvn 未独立安装，用 IDEA 自带 Maven 跑命令行测试可行。
